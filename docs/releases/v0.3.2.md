## Highlights

- Successful shutter commands no longer produce a false Home Assistant error
  when the Gen 1 hub omits an acknowledgement field.
- A valid HTTP response with no explicit hub error is treated as accepted,
  matching the hub's observed fire-and-forget control behaviour.
- Genuine connection, authentication, session, malformed-response,
  unexpected-hub, and explicit non-zero `errorCode` failures remain visible.

## Upgrade notes

- No configuration or entity migration is required.
- Factory credentials, shutter positions, room and panel controls, battery
  sensors, polling, and entity identities are unchanged.
- Home Assistant cannot infer RF delivery from the hub response. If a shutter
  does not move, check its battery, pairing, RF range, and Norman repeaters.

## Verification

- Protocol regressions cover empty and metadata-only successful responses,
  explicit zero and non-zero hub error codes, and malformed error codes.
- Real Home Assistant tests keep genuine command failures translated while the
  successful command path remains notification-free.
- The local publication gate passed 106 focused tests plus 19 subtests and 89
  real Home Assistant tests on both the 2024.11 minimum and current releases.
- Strict mypy and Ruff passed. Coverage reached 95% for the Home Assistant layer,
  100% for config flow, and 97% across the complete integration.
- The release commit is also checked by the repository's HACS and Hassfest
  workflows before publication.
