# Norman v0.5.0b4 — hub reliability and Gen 2 room discovery (beta)

This opt-in beta addresses plausible causes of grouped commands moving only one
shade and missing room devices. The maintainer owns a Gen 1 hub only: automated
fixtures do not confirm these fixes on a physical Gen 2 hub. Stable v0.4.1 remains
available. This beta retains the earlier v0.5 ESPHome RF and schema work.

## What changes

- Individual and room commands share a per-hub queue with at least 750 ms between
  control request starts. Separate hubs have independent queues.
- Commands include the registered hub identity and distinct timestamps and task
  IDs. A backwards or stalled wall clock does not immediately reuse identifiers.
- Room IDs supplied as decimal strings are accepted alongside integer IDs. Bools,
  fractional values and malformed identities cannot create a room cover.
- Bottom-only shades omit the middle rail. Tilt is offered only for reported
  second rails; an intermittently missing known rail still blocks preservation.
- Status requests wait for command bursts, with a 35-second follow-up and
  60-second idle polling. Opening/closing reflects accepted or reported targets.
- Gen 1 transient login HTTP 500s receive bounded delayed retries and retain the
  last good snapshot for up to two failed polls after successful setup.
- Missing-room troubleshooting gains diagnostic counts, original ID-type counts
  and rejection reasons. Warnings omit raw IDs, names and API payloads.

Room commands still control each shade in sequence, preserving its own other
rail. They are not native simultaneous broadcasts. Partial failures stop further
commands and report uncertainty; there are no automatic retries or rollback
movements. Existing individual and valid integer-room identities are preserved.

## Try the beta

1. Back up Home Assistant and note your currently installed Norman version.
2. In HACS, open Norman's three-dot menu, choose **Redownload**, then **Need a
   different version?**, select **v0.5.0b4** and restart Home Assistant. Older HACS
   versions may require **Show beta versions**. Use **Update information** if the
   release is not yet listed; the README also describes manual installation.
3. Under **Settings → Devices & services → Norman**, open the Gen 2 devices list.
   Each discovered non-empty room should have its own device named after the room,
   containing a **Shades** cover. Individual shades remain available.
4. With the shades in view and travel paths clear, test individual controls, then
   one existing HA cover group and one room cover: Open, Close and a mid-position.
   Confirm all intended members respond and other rooms stay still. Sequential
   movement is expected. Stop after any unexpected movement or failure and check
   actual positions before sending another command.
5. Where possible, include one bottom-only shade and a mixed room. Confirm tilt
   is absent for those covers and bottom movement does not move a second rail.
6. If rooms are still missing, download diagnostics from the Gen 2 entry's
   three-dot menu. Include the download, Home Assistant/Norman versions and the
   observed behaviour in issue #26. Report group-command results in issue #25.

An optional, disabled-by-default **Battery reading** diagnostic sensor exposes
the Gen 2 value unchanged without units or conversion. A reading of 3.7 remains
3.7. The protocol units need evidence before a battery percentage can be inferred.

Session batching, removal of Gen 1 logout calls, native Gen 2 broadcasts, movement
retries, Favourite buttons, individual-motor covers and extra Gen 1 sensors are
not included. These are separate protocol or feature changes requiring their own
qualification.

## Return to your previous version

Select your recorded version in HACS and restart Home Assistant. Do not delete
and recreate the integration. If configuration restoration is necessary, use the
pre-test Home Assistant backup. Room entities added by the beta are separate from
existing individual covers.
